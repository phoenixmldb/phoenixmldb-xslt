# Real-world engine repros

The W3C conformance corpora do not catch the bugs real stylesheets hit. Every regression
reported from the field so far (DocBook XTDE0420, XSpec XTTE0505) passed the full unit and
conformance suites. This skill runs the engine against actual production stylesheets.

Remember: the conformance suite asserts only `passed > 0`, so **it cannot fail on a
regression**. A green conformance run is not evidence. The unit suite (1204 tests) is the
real gate.

## Quickstart — DocBook xslTNG

```bash
S="$(git rev-parse --show-toplevel)/.claude/skills/engine-repro/scripts"   # from anywhere in this repo
dotnet build src/PhoenixmlDb.Xslt.Cli/PhoenixmlDb.Xslt.Cli.csproj -f net10.0
$S/bootstrap-xsltng.sh     # one-time per checkout (~30s); re-run after changing xslTNG sources
$S/run-docbook.sh          # PASS/FAIL + non-zero exit on failure
```

`run-docbook.sh` asserts landmarks in the output (doctype, `</html>`, title, `<h1>`, body
prose, generator meta) — a silent exit 0 with a truncated document still fails. Both failure
modes (transform error, missing landmarks) exit 1, so it is safe to use as a gate.

Takes an optional source document: `run-docbook.sh path/to/doc.xml`.

## Why bootstrap is needed

`/repos/phoenixml/docbook/xslTNG` is a **source checkout**, not a release. `src/main/xslt` is
not runnable — `main.xsl` imports three modules Gradle generates at build time. Each is
produced by an XSLT transform, so the bootstrap generates them with **our own engine** (no
Java, Gradle, or network), which doubles as a self-hosting smoke test:

| Generated | From | Gradle task |
|---|---|---|
| `param.xsl` | `tools/generate-parameters.xsl` ← `src/guide/xml/ref-params.xml` | `makeXslt` |
| `VERSION.xsl` | `tools/version.xsl` (self-transform, `-p version -p gitref`) | `makeVersion` |
| `locale/en.xml` | `src/main/xslt/modules/xform-locale.xsl` ← `src/main/locale/en.xml` | `generateLocales` |

Everything lands in `build/xslt/`, mirroring Gradle's layout. Pass `--all-locales` for all 75
(only `en` is needed for the sample).

Martin reports against **release** distributions (2.8.0, 2.8.3), where these files were
generated by Saxon. Ours are engine-generated, so a discrepancy can in principle originate in
the bootstrap rather than the transform — if a repro disagrees with Martin's, diff the
generated `param.xsl` first.

## Diagnostics

`PHXDIAG_XTDE0420=1` dumps construction state at all five XTDE0420/0440 raise sites in
`XsltTransformer.cs` — the attribute being added, `_documentNodeDepth`, `_attributeCollecting`,
`_output` length vs `_outputLogicalStart`, the scope-local content, and a filtered stack:

```bash
PHXDIAG_XTDE0420=1 $S/run-docbook.sh
```

Read the stack for the **innermost construction frame** (`BindVariableAsync`,
`CreateLiteralElementCoreAsync`, `CreateDocumentAsync`) — that is the scope whose rules the
guard is applying, and it is usually the bug, not the instruction that tripped it.

### Tracing `_documentNodeDepth` balance

When a guard fires and the enclosing scope looks innocent, the depth may have been inherited
or leaked. Insert a tracer after every mutation:

```bash
cd /repos/phoenixml/phoenixmldb-xslt
python3 - <<'PY'
import re
p='src/PhoenixmlDb.Xslt/Engine/XsltTransformer.cs'
lines=open(p,encoding='utf-8').read().split('\n')
t=[i for i,l in enumerate(lines) if l.strip() in ('_documentNodeDepth++;','_documentNodeDepth--;')
   or re.fullmatch(r'_documentNodeDepth = [A-Za-z0-9_]+;', l.strip())]
for i in reversed(t):
    ind=re.match(r'\s*',lines[i]).group(0)
    lines.insert(i+1, f'{ind}Console.Error.WriteLine($"[docDepth] L{i+1} -> {{_documentNodeDepth}}");')
open(p,'w',encoding='utf-8').write('\n'.join(lines))
print('instrumented', len(t), 'sites')
PY
```

Tally the sites afterwards (`grep -o 'L[0-9]*' | sort | uniq -c`). Balanced `++`/`--` counts
mean the depth is legitimately owned by a live scope; an unmatched `++` means a leak. Revert
with `git checkout src/PhoenixmlDb.Xslt/Engine/XsltTransformer.cs` — **check `git diff` first
if a real fix is in progress in the same file.**

## Verifying a fix

```bash
cd /repos/phoenixml/phoenixmldb-xslt
dotnet test tests/PhoenixmlDb.Xslt.Tests/PhoenixmlDb.Xslt.Tests.csproj -f net10.0   # gate: 1204 pass, 0 fail
$S/run-docbook.sh                                                                   # real-world check
```

A cold restore-and-build is ~10 min; an incremental engine build ~4 min. Budget for it.

## What the bootstrap doubles as

Generating `param.xsl` runs our engine over `generate-parameters.xsl`, which is an unusually
good namespace-serialization stress test: `xsl:namespace-alias` puts the result root in the
XSL namespace and `<xsl:namespace name="xsl">` then re-declares that same binding. Emitting
both produced a duplicate `xmlns:xsl` and non-well-formed output — fixed in
`CreateNamespaceAsync`, and the bootstrap now scans the generated file for duplicate attribute
names so a regression fails there rather than as a confusing import error downstream.

## Known open issues that affect repros

- **XSpec `XTTE0505`** on typed-template copy — still open; blocks `gather-specs.xsl`. The

## Adding a target

Drop a `run-<target>.sh` in `scripts/` following `run-docbook.sh`: run the transform, check
the exit code, then assert landmarks in the output. Corpora live at
`/repos/phoenixml/docbook/xslTNG`, `/repos/phoenixml/martin/` (Martin Honnen's repros and
notes), and `/repos/phoenixml/martin/xspec`.
