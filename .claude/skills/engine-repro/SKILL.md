# Real-world engine repros

The W3C conformance corpora do not catch the bugs real stylesheets hit. Every regression
reported from the field so far (DocBook XTDE0420, XSpec XTTE0505) passed the full unit and
conformance suites. This skill runs the engine against actual production stylesheets.

Remember: the conformance suite asserts only `passed > 0`, so **it cannot fail on a
regression**. A green conformance run is not evidence. The unit suite (1863 tests) is the
real gate.

Stronger, from 2026-09-16: an A/B conformance sweep over both the #129 and #132 fixes came
back with **byte-identical failure sets** — 334 cases each arm, zero movement. That result was
correct and uninformative. It proved nothing broke; it said nothing about whether either fix
worked, because the W3C suite contains no test for either shape. Both fixes were demonstrated
by a real-stylesheet corpus and a Saxon reference verdict, and by nothing else.

## Quickstart — DocBook xslTNG

```bash
S="$(git rev-parse --show-toplevel)/.claude/skills/engine-repro/scripts"   # from anywhere in this repo
dotnet build src/PhoenixmlDb.Xslt.Cli/PhoenixmlDb.Xslt.Cli.csproj -f net10.0
$S/bootstrap-xsltng.sh     # one-time per checkout (~30s); re-run after changing xslTNG sources
$S/run-docbook.sh          # PASS/FAIL + non-zero exit on failure
```

`run-docbook.sh` asserts landmarks in the output (doctype, `</html>`, title, `<h1>`, body
prose, generator meta) — a silent exit 0 with a truncated document still fails. Both failure
modes (transform error, missing landmarks) exit 1, so it is safe to use as a gate.

Takes an optional source document: `run-docbook.sh path/to/doc.xml`.

## Why bootstrap is needed

`/repos/phoenixml/docbook/xslTNG` is a **source checkout**, not a release. `src/main/xslt` is
not runnable — `main.xsl` imports three modules Gradle generates at build time. Each is
produced by an XSLT transform, so the bootstrap generates them with **our own engine** (no
Java, Gradle, or network), which doubles as a self-hosting smoke test:

| Generated | From | Gradle task |
|---|---|---|
| `param.xsl` | `tools/generate-parameters.xsl` ← `src/guide/xml/ref-params.xml` | `makeXslt` |
| `VERSION.xsl` | `tools/version.xsl` (self-transform, `-p version -p gitref`) | `makeVersion` |
| `locale/en.xml` | `src/main/xslt/modules/xform-locale.xsl` ← `src/main/locale/en.xml` | `generateLocales` |

Everything lands in `build/xslt/`, mirroring Gradle's layout. Pass `--all-locales` for all 75
(only `en` is needed for the sample).

Martin reports against **release** distributions (2.8.0, 2.8.3), where these files were
generated by Saxon. Ours are engine-generated, so a discrepancy can in principle originate in
the bootstrap rather than the transform — if a repro disagrees with Martin's, diff the
generated `param.xsl` first.

### Getting the release Martin actually ran — do this instead of bootstrapping

**xslTNG 2.8.x is not on GitHub.** `gh release list --repo docbook/xslTNG` tops out at 2.7.1,
and the `VERSION-ID` in Martin's `VERSION.xsl` is not a commit in that repo. Concluding "2.8.0
was never released" from GitHub alone is wrong and has cost a session already. Releases ship
from the DocBook CDN, browsable file-by-file (no zip):

```
https://cdn.docbook.org/release/xsltng/<version>/release/xslt/
    docbook.xsl param.xsl VERSION.xsl standalone-functions.xsl catalog.xml …
    transforms/ (11)   modules/ (49)   locale/ (75)
```

Index pages write attributes with **single quotes**, so `grep 'href="…"' ` silently returns
nothing. Downloading `xslt/` (73 files) gives Martin's exact environment: `variable.xsl`,
`param.xsl` and `VERSION.xsl` come back **byte-identical** to the copies in
`repros/martin/docbook/`. A release ships those files pre-generated, so **no bootstrap is
involved** and the caveat above does not apply.

Global-variable failures reproduce with any well-formed DocBook article — a 437-byte one is
enough — because they fire during global initialisation. Do not wait on Martin for a source
document before trying.

## Diagnostics

`PHXDIAG_XTDE0420=1` dumps construction state at all five XTDE0420/0440 raise sites in
`XsltTransformer.cs` — the attribute being added, `_documentNodeDepth`, `_attributeCollecting`,
`_output` length vs `_outputLogicalStart`, the scope-local content, and a filtered stack:

```bash
PHXDIAG_XTDE0420=1 $S/run-docbook.sh
```

Read the stack for the **innermost construction frame** (`BindVariableAsync`,
`CreateLiteralElementCoreAsync`, `CreateDocumentAsync`) — that is the scope whose rules the
guard is applying, and it is usually the bug, not the instruction that tripped it.

### Tracing `_documentNodeDepth` balance

When a guard fires and the enclosing scope looks innocent, the depth may have been inherited
or leaked. Insert a tracer after every mutation:

```bash
cd /repos/phoenixml/phoenixmldb-xslt
python3 - <<'PY'
import re
p='src/PhoenixmlDb.Xslt/Engine/XsltTransformer.cs'
lines=open(p,encoding='utf-8').read().split('\n')
t=[i for i,l in enumerate(lines) if l.strip() in ('_documentNodeDepth++;','_documentNodeDepth--;')
   or re.fullmatch(r'_documentNodeDepth = [A-Za-z0-9_]+;', l.strip())]
for i in reversed(t):
    ind=re.match(r'\s*',lines[i]).group(0)
    lines.insert(i+1, f'{ind}Console.Error.WriteLine($"[docDepth] L{i+1} -> {{_documentNodeDepth}}");')
open(p,'w',encoding='utf-8').write('\n'.join(lines))
print('instrumented', len(t), 'sites')
PY
```

Tally the sites afterwards (`grep -o 'L[0-9]*' | sort | uniq -c`). Balanced `++`/`--` counts
mean the depth is legitimately owned by a live scope; an unmatched `++` means a leak. Revert
with `git checkout src/PhoenixmlDb.Xslt/Engine/XsltTransformer.cs` — **check `git diff` first
if a real fix is in progress in the same file.**

## Verifying a fix

```bash
cd /repos/phoenixml/phoenixmldb-xslt
dotnet test tests/PhoenixmlDb.Xslt.Tests/PhoenixmlDb.Xslt.Tests.csproj -f net10.0   # gate: 0 fail
$S/run-docbook.sh                                                                   # real-world check
```

A cold restore-and-build is ~10 min; an incremental engine build ~4 min. Budget for it.

## What the bootstrap doubles as

Generating `param.xsl` runs our engine over `generate-parameters.xsl`, which is an unusually
good namespace-serialization stress test: `xsl:namespace-alias` puts the result root in the
XSL namespace and `<xsl:namespace name="xsl">` then re-declares that same binding. Emitting
both produced a duplicate `xmlns:xsl` and non-well-formed output — fixed in
`CreateNamespaceAsync`, and the bootstrap now scans the generated file for duplicate attribute
names so a regression fails there rather than as a confusing import error downstream.

## Checks that cannot fail

The recurring way these investigations go wrong is not a wrong hypothesis — it is a check
structurally unable to see the thing it was asked about, which then returns the comfortable
answer. Seven of these occurred in a single session on 2026-09-16:

| what ran | why it saw nothing | how it read |
|---|---|---|
| `xslt … -o /dev/null` | the measurement was in the *output* | "probe printed nothing" |
| `find / -xdev` | never crossed onto the `/mnt/data` mount | "corpus is absent" |
| `grep 'href="…"'` | the page used single quotes | "directory is empty" |
| a probe inserted after the *first* `</xsl:variable>` | landed out of scope | "no count printed" |
| `dotnet run --no-build` after a **failed** build | ran the previous binary | "the fix changed nothing" |
| a diagnostic printing `LocalName` | two globals differed only by the `vp:` prefix | "both appends identical" |
| a gate script whose patch path was rewritten by `sed` | gated an **unpatched** tree | a perfectly green row |

Rules that follow, each paid for:

- **Print evidence, not verdicts.** `logs=11 timeouts=0` is checkable; `timeouts=0` is not.
- **A failing build must stop the run.** Grep the build output for ` error `, never for success.
- **The engine under test cannot decide when a cross-engine artifact is complete.** A cut-down
  reproduction grown until *our* engine stopped complaining still failed Saxon's static
  analysis at an unrelated line — "both engines fail" would have been corroboration from two
  unrelated failures. Close such a set **statically** instead: every referenced global, param
  and function declared within it.
- **Reproduce on the real stylesheet before reducing.** Eleven minimal reproductions of the
  #129 and #132 defects were refuted; both were solved by instrumenting the real file and by
  running it across every available build. A mock that does not reproduce rules out nothing —
  the default conclusion is "my shape is wrong", never "the engine is fine".
- **Verify HEAD before quoting any measurement.** A local `main` six commits behind
  `origin/main` produced three A/B comparisons between two nearly identical builds.

Every one of these is a **plumbing** defect, not a logic defect. Nobody wrote a wrong
assertion; the assertion never received the data — wrong file, wrong quoting, wrong scope,
wrong binary, wrong stream. Reviewing the assertion finds none of them, which is why they
survive scrutiny that would catch a wrong test.

So the remedy is a counterfactual aimed at the **instrument** rather than the claim: **make
the check fail once on purpose.** Break the thing it is meant to catch and confirm it goes
red. That is the only technique that catches all seven above — and a check never observed
failing has not been tested, it has been run. For counters, state the number even when it is
zero and assert the input was non-empty first: `timeouts: 0` from an empty glob and from a
clean run are the same three characters. (BUGS #107.)

## Known open issues that affect repros

- **`TestData/` conformance corpora** silently skip when absent, returning green.
- **XSpec `XTTE0505`** on typed-template copy — still open; blocks `gather-specs.xsl`. The
  unit suite carries a skipped test for it
  (`TypedTemplateInsideConstructionTests.TypedTemplate_NestedInsideParentCopy_...`).

## Adding a target

Drop a `run-<target>.sh` in `scripts/` following `run-docbook.sh`: run the transform, check
the exit code, then assert landmarks in the output. Corpora live at
`/repos/phoenixml/docbook/xslTNG`, `/repos/phoenixml/martin/` (Martin Honnen's repros and
notes), and `/repos/phoenixml/martin/xspec`.
